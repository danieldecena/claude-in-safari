## Decision log
### 2026-10-13
- Finding (root cause, the "iCloud Mail tab refuses scripts" bug): it is not about iCloud Mail or about the tab being restored. A tab Safari restored **but never showed** has no web content: `tabs.get` reports its real URL and `status: "complete"`, yet `webNavigation.getAllFrames` fails with "Main frame not found" and `executeScript` returns nothing, so `inPage` burned its 5 s retry budget and reported "did not accept the script". `tabs.reload` does **not** load such a tab (verified: frames still missing afterwards). Showing the tab for a moment does. A restored tab that comes back as the *active* tab is loaded already, which is why a fresh Mail tab and restored LinkedIn tabs always worked and the failure looked site-specific. The `debug_tab` probe is what exposed it (frames ERR + `exec: [null]` against a normal-looking `tabs.get`).
- Decided: `inPage` calls `wakeIfUnloaded` once per call, on the top frame only, when the first attempt produced nothing. It activates a background tab with no frames for 350 ms, puts the previously active tab back, and retries; the load continues after the switch. A tab that has a main frame but still refuses scripts (`favorites://`) never reaches this path, so it keeps its old 5 s failure and does not steal focus. Measured in STP: first call on an unloaded restored tab 2016 ms, second call 59 ms, active tab unchanged, `get_page_text` on it returns the page.
- Decided: keep the `debug_tab` method in `background.js`. It is not registered as an MCP tool (only reachable from a relay client), costs no tool schema, and is the only way to see the frames-versus-`tabs.get` mismatch that this bug turned on. It landed in `main` via the 15:17 auto-commit rather than deliberately, which is now moot.
- Finding: every `scripts/build-notarized.sh` run re-registers the **DerivedData** copy of the appex with pluginkit, which silently displaces the `~/Applications` one. STP then launches with no extension context at all (Safari 27.2 kept its existing one). Registering the installed copy fixes that, but leaves both paths known, and then each browser loads **both** copies: Settings > Extensions shows two "Claude in Safari" rows (Daniel's screenshot) and the bridge reports two contexts per browser listing the same tabs under different ids (STP: [106,113,219] and [104,111,217] for the same three tabs).
- Decided: `scripts/install-app.sh` owns installation. It replaces `~/Applications/Claude in Safari.app`, de-registers every appex path that is not the installed one, registers that one, and opens it. Use it instead of a bare `ditto` after `build-notarized.sh`; browsers still need a quit and reopen to drop the old copy.
- Decided: `javascript` accepts `await` (content.js v10). Code that fails to parse because of a top-level `await` is re-run as an async function; the promise is parked in the page and background polls `window.__cis.poll(id)` every 100 ms for up to 12 s. The eval wrapping was checked in Node (sync, undefined, async return, async throw, bare promise, `return` without `await` still a SyntaxError). Live in Safari 27.2 the same day: bench `javascript async` 409 ms on example.com, `window.__cis.version` 10, async `return`/`throw` both delivered, never-settling promise rejected at 12211 ms. Console lines logged after the first `await` are not captured (the console wrap is restored when the sync part returns).
- Decided: `batch` pins the tab's socket for its duration, so steps stop paying a `tabs_context` round trip to every browser each; resolved at the first non-wait step so a wait-only batch makes no lookup. Also: a non-numeric `wait` is 0 ms (was `NaNms`), and a schema failure is reported on one line (`action: Invalid option...`) instead of Zod's JSON dump. Bridge tests 11/11, and the harness now kills leftover bridge children in an `after` hook so a failing test cannot hang `node --test`.
- Finding: the toolbar icon looked blurry (Daniel's screenshot, tinted toolbar). The twelve 0.06-weight hairlines from 2026-09-29 blur into a gray blob once Safari tints the alpha, at every size. Redrawn with `scripts/make-toolbar-icons.py` (ImageMagick): 8 spokes at 0.10 weight for 24 px and under, 12 spokes at 0.085 with a near-solid centre for 32 px and up (what a Retina Mac renders for a 16-20 pt button). The thinning in September was to stop the centre merging; the spokes now start further out instead.
- Decided: the toolbar popup is a small dashboard (Daniel's screenshot showed one status line, "Last command: tab, 30s ago" and a Reconnect button that did nothing useful while connected). It now shows browser, Claude session count and bridge uptime from a new `{type:"status", sessions, bootedAt}` message the bridge sends each extension socket on connect and on every relay join or leave (bridge test 12/12), the last five commands with the tab title they hit, and the extension and content.js versions; Reconnect appears only while waiting. Shipped in the 15:17 notarized build; both Safari 27.2 and STP contexts restarted at 15:18.
- Finding: an auto-commit process ("Auto-commit session changes", co-authored Haiku 4.5) committed and pushed this session's working tree at 15:17, including the `debug_tab` probe in `extension/background.js` that was meant to stay uncommitted. It is harmless (bridge never exposes it) but is now in `main`.
- Finding: the toolbar icon fix is confirmed by Daniel's screenshot (crisp 12-spoke spark beside Safari's own glyphs).
- Finding: the shipped build is `scripts/build-notarized.sh` output installed to `~/Applications` (notarytool Accepted, stapled, spctl "Notarized Developer ID"); the repo moved to `~/Developer/safari/claude-in-safari` (the plan's `~/developer/claude-in-safari` path is stale).
