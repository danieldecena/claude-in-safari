# Claude in Safari

A Safari Web Extension plus a localhost MCP bridge that lets Claude Code drive real,
logged-in Safari (or Safari Technology Preview) tabs the way Claude in Chrome drives
Chrome: list tabs, navigate, read the page, click, type, screenshot, run JS, read the
console — all while the browser stays in the background.

## How it works

```
Claude Code ── stdio (MCP) ── bridge/server.js ── ws://127.0.0.1:18765 ── extension background page ── content.js in each tab
```

- The bridge owns the socket because a Safari background page cannot listen; it can
  only dial out. The extension reconnects on its own (backoff up to 5s, plus a
  1-minute alarm that revives a suspended worker).
- Each browser and each Safari profile loads its own extension context with its own
  `safari-web-extension://` origin; the bridge keeps one socket per origin and groups
  tools like `tabs_context` by context.
- Connections must present the shared token (see Security below).

## Layout

| Path | What it is |
|------|------------|
| `extension/` | The web extension: `manifest.json` (MV2 — see Constraints), `background.js` (socket + tab-level methods), `content.js` (page tree, refs, actions, console capture) |
| `Claude in Safari/` | Xcode wrapper app generated by `safari-web-extension-converter`; builds the extension into an `.appex` |
| `bridge/` | Node MCP server (`server.js`), stdio-launched by Claude Code |

## Building cold

Prereqs: macOS 27, Xcode 27 beta, Node 24, pnpm, Safari Technology Preview.
Signing needs the free Apple Development cert (personal team) — ad-hoc
"Sign to Run Locally" fails silently (Safari logs "Computing the code signing
dictionary failed" and the extension never connects).

```sh
cd bridge && pnpm install && cd ..
xcodebuild -project "Claude in Safari/Claude in Safari.xcodeproj" \
  -scheme "Claude in Safari" -configuration Debug \
  -derivedDataPath DerivedData build
open "DerivedData/Build/Products/Debug/Claude in Safari.app"
```

Then in STP: Settings → Extensions → enable Claude in Safari and grant it access to
all sites. Rebuilding after an `extension/` change requires relaunching Safari (or
toggling the extension off and on) to load the new copy.

## Registering with Claude Code

From the repo root (local scope, so the tools only appear in sessions here):

```sh
claude mcp add claude-in-safari -- node "$PWD/bridge/server.js"
```

Tools: `tabs_context`, `navigate`, `get_page_text`, `read_page`, `find`,
`computer` (click / type / key / scroll), `javascript`, `read_console`,
`screenshot`, `ping`.

## Security

Any Safari extension gets a `safari-web-extension://` origin, so origin alone does
not identify this one. The extension appends `?token=<CIS_TOKEN>` when dialing, and
the bridge — which parses the constant out of `extension/background.js` at startup,
the single place it is defined — refuses any connection without it (verified: right
origin + no token, wrong token, and right token + web origin are all rejected).
To rotate: change `CIS_TOKEN` in `extension/background.js`, rebuild the app, reload
the extension, restart the bridge. The bridge binds 127.0.0.1 only.

## Testing the connection

```sh
cd bridge && pnpm spike
```

No MCP; logs a ping round-trip and worker uptime every 30s. `uptimeMs` resetting
between pings means Safari killed and restarted the background page.

## Constraints and known limits

- **Manifest v2, not v3.** In Safari/STP, MV3 `service_worker` never loads
  (`WKWebExtensionContextErrorDomain` Code=6) and MV3 event pages are unloaded ~30s
  after load. An MV2 background page stays up. Consequence: no `chrome.scripting`;
  content scripts go in via the manifest plus `tabs.executeScript`.
- **Clicks are untrusted.** Safari has no equivalent of Chrome's `debugger`
  permission, so `computer` dispatches synthetic DOM events (`isTrusted: false`).
  Sites that ignore untrusted input need the osascript fallback in
  `~/developer/safari-automation`.
- **Console capture is per-tab since injection** and pages with a strict CSP only
  capture window errors, not `console.*` calls.
- **Screenshots briefly activate background tabs** (captureVisibleTab only sees the
  active tab); the previously active tab is restored after.
